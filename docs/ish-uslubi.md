# Иш услуби — кодни бузмай ўзгартириш қоидалари

> Бу ҳужжат Claude учун ёзилган. Янги чатда дастурга ўзгартириш
> киритишдан олдин шуни ўқиш керак.
> Тузилган: 05.11.2026, в70 коди асосида.

---

## 1. Олтин қоида

**Файлни ҳеч қачон бошидан қайта ёзма.** `index.html` — 1,9 МБ, 10 700 қатор.
Тўлиқ қайта ёзиш ҳар доим нимадир йўқотади.

Тўғри усул: керакли жойни **аниқ матн бўйича топиб алмаштириш**, ва
алмаштиришдан олдин ўша матн файлда **нечта марта** учрашини текшириш.
Битта марта учраса — алмаштирилади. Иккита ёки нолта бўлса — тўхтаб,
матнни аниқлаштириш керак. Шу текширувсиз алмаштириш — хатонинг асосий сабаби.

Ишни шундай олиб бориш керак:
1. Керакли жойни қидириб топиш (функция номи, матн, CSS синфи).
2. Кичик, аниқ алмаштиришлар рўйхатини тузиш.
3. Янги катта модулни алоҳида файлга ёзиб, кодга бир жойдан улаш.
4. Синтаксисни текшириш.
5. Автомат тест билан ишлашини текшириш.
6. Фақат шундан кейин файлни бериш.

## 2. Янги модулни қаерга улаш

Янги катта бўлим коди **`function vFirm(){` қаторидан олдин** қўйилади.
У ердаги код ҳамма нарсадан кейин юкланади, шунинг учун мавжуд
функцияларни «ўраб олиш» мумкин.

## 3. Мавжуд функцияни бузмай кенгайтириш («ўраш» усули)

Мавжуд функциянинг ичини таҳрирлаш ўрнига, уни сақлаб қолиб устига қўшилади:

```js
{ const _old = vOffice;
  vOffice = function(f){
    if (янгиШарт) return янгиКўриниш(f);
    return _old(f);               // эскиси ўз ҳолича ишлайверади
  };
}
```

Шу усул билан кенгайтирилган функциялар: `vFirm`, `vContracts`, `vOffice`,
`vGtd`, `ctTabsHTML`, `ldView`, `ldCells`, `colsOf`, `colPanel`, `itemsCard`,
`ctSaCard`, `ctExecCard`, `ctAlerts`, `ctDocFilter`, `aiDoc`, `rteSync`,
`docSig`, `mmView`.

Афзаллиги: эски хулқ сақланади, бузилса фақат янги қават ўчирилади.

## 4. Маълумот билан ишлаш

| Нима қилиш | Функция |
|---|---|
| Ёзувни сақлаш / янгилаш | `putItem(kind, obj, note)` |
| Мавжуд ёзувнинг бир қисмини ўзгартириш | `attPut(kind, id, mut, note)` |
| Ўчириш (юмшоқ) | `delItem(kind, id, note)` |
| Ўқиш | `S.firms`, `S.orders`, `S.recs`, `S.gtd`, `S.emp` |

`kind` — `firms` / `orders` / `recs` / `gtd` / `emp`.
Шартнома, ҳисобот, хат, чек — ҳаммаси `recs` да, `type` майдони билан
ажратилади.

**Қоидалар:**
- Янги ёзув турини (`type`) ўйлаб топганда уни керакли рўйхатларга қўшиш
  керак: `REC_LABEL` (номи), `NEW_REC_T` (ҳужжат ИД индексига кирмаслиги
  учун), `DUP_SKIP` (дубликат қидирувидан чиқариш учун, агар техник ёзув бўлса).
- Барча фирмаларга тегишли ёзувда `firmId:"_global"`.
- Ёзувни ўзгартиришда `attPut` ишлатилади — шунда бошқа ходим айни пайтда
  бошқа майдонни ўзгартирган бўлса, зиддият аниқланади.
- `putItem` даги учинчи аргумент — журналга ёзиладиган изоҳ. У доим
  тушунарли ўзбекча жумла бўлсин: «Шартнома № 12 ўзгартирилди».

## 5. Жадвал, фильтр ва белгилаш

- Жадвал устунлари `COLS.<key>` массивида. Янги устун қўшилса, у ерга
  обьект қўшилади: `{k:"калит", t:"Сарлавҳа", d:1, v:r=>...}`. `d:1` —
  бошланғич ҳолатда кўринади.
- Жадвал `colTable(key, rows, attr)` орқали чизилади.
- Устунлар тартиби `localStorage` да сақланади — эски фойдаланувчида янги
  устун ўзи пайдо бўлмайди. Шунинг учун бир марталик кўчириш қилинади
  (`fb-ctcol68`, `fb-ctcol69` каби белги билан).
- Қаторларни белгилаб оммавий амал қилиш `SEL_MAP` орқали.

## 6. Claude билан ҳужжат ўқиш

Янги ҳужжат тури учун андоза:

```js
AI_SPEC.nomi = {
  tool:"save_xxx", sec:"bank", max:3000,
  desc:"...",                 // инглизча, қисқа
  prompt:"...",               // инглизча, ҳужжат қандай кўринишда бўлиши
  props:{ number:AI_S("..."), total:AI_N("...") }
};
```

- Ўқиш: `aiDoc(file, firm, AI_SPEC.nomi, fileName)` — PDF ва расм учун.
- Excel ёки матн учун: `aiDocAny(...)` ёки `aiCall(...)` тўғридан-тўғри.
- Жуда узун маълумот (банк кўчирмаси) **қисмларга бўлиб** юборилади,
  акс ҳолда охири кесилиб қолади.
- `aiOn()` — калит уланганми; `aiAuto(weak)` — автомат ўқишга рухсат борми.
- Харажат ҳар сафар ёзувга қўшилади: `d.ai={usd:...}`.
- Claude ўқиган маълумот **устига ёзилмайди**, балки фойдаланувчига
  текшириш учун кўрсатилади.

**Муҳим:** Claude ўқиши ихтиёрий бўлсин. Калит уланмаган бўлса ҳам,
бўлим ишлаши керак — қўлда киритиш ёки оддий ўқиш орқали.

## 7. Узоқ жараёнлар ва хабарлар

- `taskStart(сарлавҳа, n, {stoppable:true})` → `taskStep(i, матн)` →
  `taskEnd()`. Фоизли панель ўзи чиқади. `taskStopped()` — фойдаланувчи
  тўхтатдими.
- Қисқа хабар: `toast("матн")`.
- Хатони кўрсатиш: `toast(explain(err))`. `AuthErr` келса — циклни тўхтатиш
  керак, акс ҳолда ҳар бир файлда қайта-қайта хато чиқади.

---

## 8. Файллар ва ҳужжатлар

- Юклаш: `driveUpload(file, name, {firmId, sec, sub:["Папка"]})`.
  `sec` — бўлим коди, Drive'да шу номли папка очилади.
- Ҳаволани олиш: `ctFileUrl(ref)`.
- Ёзувга файл бириктириш блоки: `attachBox(kind, rec, "Сарлавҳа")`.
- Олдиндан кўриш: `pvBox(...)`.
- PDF: `pdfSave(html, name, {title})`. Бир нечта файлни бирлаштириш:
  `printMerge(refs)`.
- Word: `OF_WORD_CSS` + `saveBlob(blob, "nom.doc")`.
- Расмий бланк: `<div class="sheet ofdoc clean">` + `ofHead(f)` +
  `.oftitle` + `.regtab` ёки `.btab` жадвали + `ofSignBlock(...)`.

## 9. Дизайн қоидалари

Янги бўлим мавжудларидек кўриниши учун **фақат шу синфлар** ишлатилади.
Янги ранг ёки ўлчов ўйлаб топилмайди — CSS ўзгарувчилари олинади:
`--accent`, `--ink`, `--muted`, `--line`, `--panel`, `--bg`, `--ok`,
`--work`, `--danger`.

| Элемент | Синф |
|---|---|
| Карточка | `.card` |
| Форма | `.card.lform` + `.lgrid` + `.field` (`.wide`, `.wide2`) |
| Тугма | `.btn` (`.primary`, `.ghost`, `.sm`, `.danger`) |
| Фильтр тугмаси | `.chip` + `aria-pressed` |
| Рақамли карточкалар қатори | `.lstats` > `.lstat` (`--c`, `--cl` ранглари билан) |
| Ҳолат белгиси | `.lpill` + `ok` / `soon` / `bad` / `off` / `act` |
| Кичик «бор/йўқ» белгиси | `.poab.ok` / `.poab.no` |
| Жадвал | `.tablewrap` > `table.ltable` ёки `table.sched` |
| Рақам катаги | `class="num"`, ўнгга текислаш `class="r"` |
| Бўш ҳолат | `.empty` (ичида `<b>` сарлавҳа + тушунтириш) |

**Матн қоидалари:** ҳамма ёзув ўзбекча, кирилл алифбосида. Бўш ҳолатда
нима қилиш кераклиги ёзилади. Тугма номи — иш номи («Кўчирма юклаш»),
техник атама эмас.

## 11. Текшириш — файлни беришдан олдин мажбурий

**Тестлар тайёр ҳолда репозиторийда туради:** `tests/` папкаси.
Уларни қайта ёзиш шарт эмас — ишга тушириш керак.

```bash
bash tests/setup.sh      # бир марта: Chromium ва кутубхоналар
bash tests/run_all.sh    # барча тестлар (13 та)
bash tests/run_all.sh t_50   # фақат кераклиси
```

Ҳар бир тест охирида `ERR []` чиқиши шарт. Тўлиқ рўйхат ва янги тест
ёзиш андозаси `tests/README.md` да.

Тартиб:
1. **Синтаксис.** Бутун скрипт блоки хатосиз юкланишини текшириш.
2. **Мавжуд тестлар.** `bash tests/run_all.sh` — ҳаммаси ўтиши керак.
3. **Янги тест.** Янги бўлим қўшилса, унга `tests/t_XX_nomi.py` ёзилади
   ва у ҳам репозиторийга юкланади.
4. **Кўз билан.** Янги бўлимнинг скриншоти — жадвал қийшаймаганми,
   матн сиғганми.

**Тестсиз файл берилмайди.** «Ишлаши керак» деган гап етарли эмас.

### Ўзгариш хавфли бўлган жойлар (тегилса — албатта текшириш)

| Нима ўзгарса | Нимани текшириш керак |
|---|---|
| `COLS`, `colsOf` | Барча жадваллар: шартномалар, ГТД, ходимлар, буйруқлар |
| `ldView`, `ldCells`, `LD` | Ишончнома, ҳисоб-фактура, ТТН — тўрт бўлим |
| `ctTabsHTML` | Шартномалардаги барча юқори бўлимчалар |
| `ctEff`, `ctExec` | Шартнома суммаси, муддати, ижро фоизи, огоҳлантиришлар |
| `aiDoc`, `aiCall` | Claude ўқийдиган барча бўлимлар |
| `putItem`, `attPut` | Исталган сақлаш — база бузилмаслиги учун |
| Расмий бланк (`ofHead`) | Барча PDF ва Word ҳужжатлар |
| CSS синфлари | Бошқа бўлимларда ўша синф ишлатилганми — текшириш |

**Claude ўзи бажаради** (фойдаланувчидан сўрамасдан, лекин режани
